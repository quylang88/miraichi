## 1. Purpose
Documents the lineage and tracking flow of sports data variables as they progress from external mocks through normalization and validation filters into APIs.

---

## 2. Lineage Tracking Flow

```
[Raw File Fixture] 
       │ (raw IDs: fixture_id, comp_name)
       ▼
[MockProviderAdapter] ──> Inject sourceProviderId & trace.adapterVersion
       │ 
       ▼
[IngestionValidator] ──> Inject validationStatus & dataQualityIssues
       │ 
       ▼
[MemoryIngestionRepository] ──> Appends ingestedAt timestamps
       │ 
       ▼
[API Gateway Endpoint] ──> Exposes inputCandidateId envelope to Local AI
```

### Traceability Metadata Fields
1. **`sourceProviderId`**: Placed at the adapter parser boundary to identify origin vendor.
2. **`ingestedAt`**: Stamped by the worker job run loop at the start of normalization processing.
3. **`trace.workerRunId`**: Links the record to a specific worker execution cycle report.
4. **`validationStatus`**: Audit state confirming the match has passed required quality checks.

---

## 3. Auditing & Reconstructing Inputs
To verify predictions generated by local AI models:
* Downstream prediction traces reference the `inputCandidateId`.
* Querying the API gateway status endpoint retrieves the corresponding ingestion run metrics and origin data timestamps, allowing the exact input state to be reconstructed.
