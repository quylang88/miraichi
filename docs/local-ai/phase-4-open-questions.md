## 1. Unresolved Technical Questions

### Q1. Local AI Inference Runtime Selection
* **Question**: Which runtime best balances zero-dependency developer setup and inference latency for statistics processing?
* **Candidates**:
  * Option A: ONNX Runtime (Node.js bindings) executing small tab-tabular models.
  * Option B: Pure JavaScript/TypeScript rule-based classifier (if heuristics are preferred over neural nets).
  * Option C: Local running python daemon calling PyTorch/Scikit-learn, mediated via HTTP.

### Q2. LLM Engine and Deployment Mode
* **Question**: Should natural language explanations be generated by a small local LLM runtime (e.g. llama.cpp, Ollama, Llamafile) or an external open-weights model hosted locally?
* **Risks**: Local LLM execution requires CPU/GPU resources that might not be present on typical worker/developer laptops.

### Q3. Model Weight Distribution
* **Question**: How do we distribute and version control model weights (`.onnx` or `.gguf` files) without bloat?
* **Candidates**: Git LFS, AWS S3 buckets (downloaded on startup), npm package publishing.

### Q4. Metric Definitions for Backtesting
* **Question**: What candidate metrics should be tracked in the backtesting harness?
* **Candidates**: Brier score, log loss, mean absolute error (MAE), or simple win/loss accuracy.

### Q5. Explainability Latency
* **Question**: Generating LLM explanations synchronously during API queries will cause high response latency. Should explanations be pre-calculated by the worker during the prediction run, or generated asynchronously and cached?
