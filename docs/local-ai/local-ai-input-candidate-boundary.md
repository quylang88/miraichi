# Local AI Input Candidate Boundary

* **Status**: Draft
* **Date**: June 23, 2026

---

## 1. Boundary Context
This document specifies how the local AI service (`apps/local-ai`) consumes raw match and market snapshots generated by the ingestion layer (`apps/worker`). The boundary isolates the prediction engine from raw, provider-specific feed changes, ensuring it only processes standardized, validated data.

---

## 2. Ingestion Handoff Mechanics
The ingestion worker caches normalized fixtures and odds. When an inference trigger occurs:
1. The system extracts a snapshot from the memory repository.
2. The validator verifies the snapshot's quality checks (e.g. valid timestamps, non-negative coordinates, positive odds).
3. The worker formats the snapshot into the standard handoff structure.
4. The handoff payload is delivered to `apps/local-ai` via local HTTP request or internal script invocation.

---

## 3. Boundary Schema Structure
The input candidate payload is defined in [ingestion-to-local-ai-handoff-contract.md](file:///c:/CODE/miraichi/docs/data/ingestion-to-local-ai-handoff-contract.md). It contains only normalized properties:

* **Identification & Context**:
  * `inputCandidateId`: Unique ID representing the generated snapshot instance.
  * `matchId`: Reference to the generic match fixture.
  * `competitionId` / `seasonId`: Context IDs to align historical stats.
* **Lineage & Source Trace**:
  * `sourceProviderId`: Source tracker string (e.g., `provider-mock-alpha`).
  * `ingestedAt`: ISO-8601 UTC timestamp of normalized storage.
* **Audit & Validation Telemetry**:
  * `freshnessStatus`: High-level latency state (`fresh`, `stale`, `delayed`).
  * `validationStatus`: Check outcomes (`passed`, `failed`).
  * `dataQualityIssues`: String array tracking validator logs.
* **Feature Indexes**:
  * `availableMarkets`: Mapped array of normalized markets (e.g., `["1X2"]`).
  * `trace`: Trace metadata (`workerRunId`, `adapterVersion`).

---

## 4. Input Exclusions
To maintain strict architectural isolation, the input candidate envelope **must not** contain:
* Machine learning features (e.g., team rolling average goal differences, normalized Elo scores, injury weight indicators).
* Model-specific pre-processing arrays or tensors.
* Any algorithm recommendations, odds probability translations, or rating predictions.
* User bankroll, active bet slips, or risk parameters.
